# Editor Enhancers

TartarusEngine's own take on kubacho lab's *Editor Enhancers* bundle for Unity: vHierarchy 2,
vFolders 2, vInspector 2, vTabs 2, vFavorites 2 and vRuler. The features are built into the
editor rather than shipped as a plugin, and they extend existing systems (selection history,
asset favorites, the Measure tool, component presets, the shortcut registry) instead of
duplicating them.

Status by phase:

| Phase | Feature set | Status |
| --- | --- | --- |
| 0 | Shared infrastructure | Done |
| 1 | vHierarchy: row styles, separators, tree lines, component minimap, scene selector, nav bar, hover keys | Planned |
| 2 | vFolders: folder styles, rules, auto icons, content minimap, bookmarks | Planned |
| 3 | vInspector: nav bar, floating component windows, multi-component copy/paste, keep play-mode changes, attributes | Planned |
| 4 | vTabs: tab strips in the Inspector and Asset Browser | Planned |
| 5 | vFavorites: hold-Alt favorites overlay with pages | Planned |
| 6 | vRuler: Shift+R surface, bounds and reference-object measuring | Planned |

### Identity and persistence

* Entities are referenced by **scene GUID + `OrderComponent` value**, never by `entt::entity`.
  entt ids are recycled across undo, Play/Stop and reloads; Order is the editor's existing
  persistent identity.
* Icons are stored by **Font Awesome name** (`"cube"`, `"folder-open"`), not by codepoint, so a
  style still resolves after the font header is regenerated. Unknown names are dropped on load.
* Colours are packed like `IM_COL32` in memory and written as `#RRGGBB` / `#RRGGBBAA` on disk.
* Both per-user files are written through `AtomicFile`, at most once per frame. Like
  `editor_prefs.json` and `asset_favorites.json`, they are journaled by the global file undo:
  bookmarking or editing the palette can be undone (labels "Edit Bookmarks" / "Edit Style
  Palette"), and `ReloadHistoryFiles` reloads them when an undo restores them.
* Unknown top-level keys in `enhancers_<hash>.json` survive a load/save round trip, so a file
  written by a newer build isn't stripped by an older one.

## Hover keys

vHierarchy, vFolders and vInspector act on **whatever is under the mouse**, whichever panel has
keyboard focus. The shortcut dispatcher (`EditorLayer.cpp`, `Shortcuts::BeginFrame`) adds three
contexts for this:

| Context | Set while the mouse is over |
| --- | --- |
| `Ctx_HierarchyHover` | Hierarchy |
| `Ctx_ProjectHover` | Asset Browser |
| `Ctx_InspectorHover` | Inspector |

Rules:

* Hover contexts are withheld while an item is active (a drag, a field being edited) and during
  Right-drag fly. A focused text field already suppresses every shortcut.
* While a hover context is set and the mouse is **not** over the Scene viewport, `Ctx_Viewport` is
  withheld. Without this, E over the Hierarchy (with focus still on the Scene) also switched the
  gizmo to Rotate.
* `Shortcuts::Conflicts` treats a hover context as overlapping its own panel's focus context: both
  can be set in the same frame, so the same chord in both would double-fire.
* The bindings appear under the "(hover)" groups in Preferences > Shortcuts and can be rebound.
* Preferences > Editor Enhancers > **Hover keys** turns the whole mechanism off.

## Shortcut changes

* **Toggle Statistics** moved from Ctrl+Shift+T to **Alt+Shift+T**. Ctrl+Shift+T is reserved for
  vTabs' "reopen closed tab". A saved override in `shortcuts.json` still wins.

## Measure tool units

The Measure tool now formats lengths through `Enhancers::FormatLength`, which vRuler shares:

* Metric adapts its unit: `4.2 mm`, `37.5 cm`, `1.840 m`, `2.31 km`.
* Imperial shows feet and inches: `5' 10.9"`, and miles from 5280 ft.

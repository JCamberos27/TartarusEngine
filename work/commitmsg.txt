Fix: a saved input list can no longer lose a default action

project/settings.json carries an "input" array, and ProjectSettings::Load used
to let it replace InputMap::Defaults() wholesale:

    InputMap::Actions() = actions.empty() ? InputMap::Defaults()
                                          : std::move(actions);

The file only holds the actions that existed the last time it was written, so
any default added since then was simply absent from the live map - and
InputMap::Lookup only warns once about a name it cannot find, which reads as
"the key does nothing". Adding an action to Defaults() was therefore silently a
no-op for every project that already had saved bindings.

That is why the EmptyReload debug binding (G) shipped dead: Defaults() had it,
the saved list had 13 actions and no EmptyReload, so G was never registered.
Relaunching could not have helped.

The merge now lives in InputMap::MergeDefaults and tops a non-empty list up
with every default it does not name, leaving the file's own entries and their
bindings untouched - so a deliberate rebind still wins over the default.

Verified: build exit 0; unit tests 804 checks / 0 failures (4 new assertions
cover exactly this: each default present exactly once, no duplicate of the
saved action, the saved binding of 71 surviving, and EmptyReload coming back);
smoke FPS_Animation_smoke_play.json PASS newGlErrors=0 newLogErrors=0
drawCalls=1 playCycles=2 variants: 0x00=220, identical to baseline.
Apartment=6 / Sandbox=1 unchanged (missing-asset environment noise).

Separately, the MagCheck arms defect is now diagnosed from the user's screen
recording: the magazine floats detached in mid-air while the left hand stays
planted at the mag well (hand_l IS animating - it travels to the well and back
- it just never meets the magazine). work/export_clip.py's header records that
the .blend was saved with the weapon parked on A_W_Tac_Reload, and all clips
written in the 4:00:42 batch predate the A_FP_x -> A_W_x pairing rule. So
A_FP_Tac_Reload was baked against A_W_Tac_Reload and is correct by accident
(which is why TacReload looks right), while A_FP_Mag_Check was baked against
the same TacReload magazine path but plays A_W_Mag_Check in engine - the hand
chases the wrong animation. Re-exporting the stale clips is NOT done here; it
needs the .blend and the user's go-ahead.

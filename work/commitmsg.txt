FPS: add a temporary G binding that plays the unreachable EmptyReload state

EmptyReload is fully authored - it has its own arms clip (A_FP_Empty_Reload),
its own weapon clip (A_W_Empty_Reload) and is a Committed-tier state - but
nothing can ever reach it: main.cpp hardcodes the Reload key to TacReload, and
there is no ammo system to decide that the magazine is empty. It therefore
could not be eyeballed at all.

InputMap::Defaults() gains an "EmptyReload" action on G (R/F/V/T/H, W/A/S/D,
Space, Shift, Ctrl, Alt, E and Esc were already taken) and main.cpp fires
TriggerAction("EmptyReload") on it. Both sites are marked TEMPORARY DEBUG and
carry a note to remove them once an ammo system decides when EmptyReload
should fire - this is not gameplay, it is a way to see the animation.

Also extends work/nodes.cpp, the probe used to reason about external-clip
channel coverage: the name filter was hardcoded to head|neck|eye|spine|camera,
so it could never show arm nodes, and it printed no parent. It now takes an
optional substring (and prints each node's parent) or "--chain <node>" to print
the full root->node ancestor chain.

That chain mode is what settles the MagCheck arms question. The suspicion was
that MagCheck leaves ~174 of the base rig's 266 nodes unanimated (its FBX has
92 nodes / 89 channels versus Inspect's 264) and that a frozen node upstream of
a skinned bone would drop the left arm to bind. It does not: hand_l's chain is
RootNode -> Armature -> root -> pelvis -> spine_01..05 -> clavicle_l ->
upperarm_l -> lowerarm_l -> hand_l, and all eleven names are in MagCheck's
channel list. The CB_/REF_ nodes are a sibling tree hanging off Armature
(CB_root's parent is Armature), never an ancestor of a skinned bone, so their
sitting at bind is harmless.

Verified: build exit 0; unit tests 800 checks / 0 failures; smoke
FPS_Animation_smoke_play.json PASS newGlErrors=0 newLogErrors=0 drawCalls=1
playCycles=2 variants: 0x00=220, identical to baseline. Apartment=6 / Sandbox=1
unchanged (missing-asset environment noise).

MagCheck's arms data is also confirmed sound by work/hand_probe: 52/52 skinned
bones driven, 0 undriven, no motionless child of a moving parent, hand_l
travelling 1085.7 mm and lowerarm_l 1172.9 mm of world-space path. All 25 clip
references in AKS74U.fpsanim resolve to real files. What still looks wrong is
therefore either the baked content or how the state plays - not missing
channels - and is not changed here.
